# Автотесты по кодексу

Правила проекта не выдумывай и не держи по памяти. Перед любой строкой теста или замечания прочитай источники в этом порядке.

## Порядок

1. Прочитай `CODEX.md` целиком. Это принятый стандарт. Замечание на ревью формулируй так, как там сказано: `кодекс 4, нет test.step`.
2. Прочитай `tests/e2e/booking-flow.spec.ts`. Это эталон каркаса: актёры, `test.step`, подготовка через API, page object, cleanup. Если сценарий трогает те же экраны, прочитай импорты эталона: `tests/Pages/booking-page.ts`, `tests/Pages/profile-page.ts`, `tests/Pages/my-slots-page.ts`, `tests/helpers/user.ts`.
3. Если пишешь сценарий по продукту, прочитай нужный раздел `requirements.md`. Поведение продукта оттуда, не из догадки.
4. Только после этого создавай тесты или оценивай чужие.

Кодекс важнее эталона. Если в `booking-flow` шаг склеен или действие экрана лежит в хелпере, в новый тест это не копируй. Гранулярность бери с половины хоста и первого гостя: отдельный степ на действие, следующий степ только с `expect`.

Слои и импорты — как в эталоне, не как строчные пути в кодексе: `tests/e2e/`, `tests/Pages/`, `tests/helpers/`. Импорт страницы: `../Pages/...`.

## Создание

Скопируй каркас эталона и подставь сценарий.

- Spec — кейс: `test` / `test.describe`, вызовы методов, `expect` внутри `test.step`.
- `tests/helpers/user.ts` — тип, `makeUser`, `registerUserViaApi`, удаление аккаунта. Новый пользователь на каждый прогон: `makeUser(role, Date.now())`. Пароль можно оставить захардкоженным, имя и почту — нет.
- `tests/Pages/<экран>-page.ts` — локаторы и действия экрана. Имя метода — смысл (`filterCatalog`, `addSkill`), не клик. `expect` в класс страницы не клади. Повторившийся локатор живёт на странице. Сначала `getByRole` / `getByLabel` / `getByTestId`.
- В spec не оставляй `getByLabel` и прочие локаторы, если страница уже есть.
- Если тест не про регистрацию, пользователя создаёт `registerUserViaApi`. UI — только для действия сценария и видимого результата.
- Каждый осмысленный шаг — `test.step` с человеческим именем и актёром, как в эталоне: `Хост: добавляет навык`. В степе-действии только открыть, нажать, ввести, выбрать. В степе-проверке только `expect`. Проверка про уже случившееся.
- Один `describe` — одна фича. Связанные проверки после одного действия — один тест. Второе, ради которого надо заново регистрироваться и повторять половину шагов, — отдельный тест.
- Нет `waitForTimeout`, `{ force: true }`, `.only`, `page.pause()`.
- Аккаунт, который тест создал, удаляется и после падения. Несколько контекстов — как в эталоне: массив `accountContexts`, `push` сразу после `newContext` и до первого действия, `test.afterEach` → `cleanupUsersViaApi`. Один контекст фикстуры `page` — `deleteUserViaApi` в `afterEach`. Тест без рабочего cleanup не готов.
- Дождись POST там, где эталон и кодекс ждут ответ (`waitForResponse` внутри метода страницы, как `addSkill` / `save`), затем проверяй состояние с сервера.

Перед тем как отдать тест, прогони затронутый spec и `npm run lint`. Красный прогон не отдавай.

## Оценка

Сначала те же два файла, потом diff или указанные spec. Не переписывай код, пока не попросили исправить.

Пиши замечания списком. Каждое — номер раздела кодекса и факт, со ссылкой на файл:

- `кодекс 4, нет test.step` — действие или `expect` вне степа
- `кодекс 1, локатор в spec` — `getByRole` / `getByLabel` в тесте при живой странице
- `кодекс 2, expect в странице` — проверка уехала из spec
- `кодекс 7, общее имя или почта` — нет своего `makeUser(role, Date.now())`
- `кодекс 9, waitForTimeout` — таймаут, `force`, `.only`, `pause`
- `кодекс 11, UI вместо API` — регистрация кликами, хотя сценарий не про регистрацию
- `кодекс 12, нет cleanup` — аккаунт не удаляется после падения, или контекст не попал в массив до первого действия

Сверь каркас с эталоном: актёр в имени степа, действие и проверка разделены, подготовка через `registerUserViaApi`, страница кликает, spec проверяет.

Вердикт одной строкой: `готов` или `не готов`. `не готов`, если есть пункт кодекса 4, 9, 11 или 12, красный прогон или пустой cleanup. Остальное тоже перечисляй.
