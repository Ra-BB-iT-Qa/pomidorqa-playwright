# PomidorQA — автотесты

Тесты сервиса коротких 25-минутных созвонов для QA. В репозитории только тесты: E2E ходят на живой стенд, API — на локальный мок, unit не выходит из процесса.

Одинаковых сценариев на одном уровне нет. Если одно правило есть и в unit, и в API, и в E2E — это слои пирамиды, а не копия теста.

Времена сняты 5 октября 2026 в Chrome, E2E одним воркером. Unit и API — весь набор зелёный за 0,4 с. E2E в этом прогоне: 31 из 40 дошли до проверки, остальные оборвались сетью стенда; для них в таблице время прошлого зелёного прогона, где оно есть.

## Скорость по уровням

| Уровень | Тестов | Где исполняется | Весь набор |
|---|---|---|---|
| Unit | 10 | функция в процессе | 15 мс |
| API | 8 | HTTP к локальному моку | 0,3 с |
| E2E | 40 | браузер на стенде | около 13 мин последовательно |

Обычный E2E без ожидания часов — 2–30 с. Дольше только тесты, которые ждут реальное начало слота: около 1–2,5 мин.

## Матрица трассируемости

Номера — разделы [спецификации](requirements.md).

### Регистрация и вход (§4)

| Уровень | Тест | Время |
|---|---|---|
| Unit | пароль короче 8 символов невалиден; ровно 8 — валиден | < 1 мс |
| API | новый участник создаётся; повтор того же email — 409 | 3 мс |
| E2E | без имени, без `@` в email, без пароля форма не уходит | 1–2 с |
| E2E | после регистрации в профиле имя, пояс Москвы, пустые Telegram и «о себе» | 4 с |
| E2E | неверный email и неверный пароль дают одну и ту же ошибку | 3 с |

Короткий пароль на самой форме отдельно не проверяется: граница в 8 символов закрыта unit-тестом.

### Профиль (§5)

| Уровень | Тест | Время |
|---|---|---|
| Unit | один момент времени печатается по-разному в разных поясах; формат «часы:минуты» | 11 мс |
| E2E | имя, Telegram, часовой пояс и «о себе» сохраняются | 2–6 с |
| E2E | кириллица в Telegram, пустое имя, навык с пустым названием | 3–19 с |
| E2E | гость видит слот в своём часовом поясе | — |

### Навыки (§6)

| Уровень | Тест | Время |
|---|---|---|
| E2E | «хочу разобрать» появляется только в своём разделе | 3 с |
| E2E | второй такой же навык «могу помочь» и «хочу разобрать» не добавляется | 3 с |
| E2E | навык удаляется, пока слот свободен и когда слот уже забронирован | 5–82 с |
| E2E | добавление навыка «могу помочь» в профиле | 3 с |

Удаление навыка при уже забронированном слоте «хочу разобрать» — самый долгий из этой группы, 82 с: там полный путь до брони.

### Слоты (§7)

| Уровень | Тест | Время |
|---|---|---|
| Unit | пересечение интервалов: нахлёст, встык, вложенность, разные часы | < 1 мс |
| E2E | слот в прошлом не создаётся | 3 с |
| E2E | второй слот раньше чем через 25 минут не создаётся; ровно через 25 — создаётся | 4 с |
| E2E | забронированный слот удалить нельзя | 9 с |

Правило «не раньше чем через 25 минут» на создании и на бронировании — границы одного ограничения, не два одинаковых теста. Unit проверяет чистую функцию пересечения, E2E — как это видно в календаре.

### Каталог и страница участника (§8, §9)

| Уровень | Тест | Время |
|---|---|---|
| E2E | в каталоге только те, у кого есть свободный слот в будущем; себя в поиске не видно | 28 с |
| E2E | поиск оставляет навык «могу помочь», а не «хочу разобрать» | внутри каталога |
| E2E | гость видит каталог и свободные слоты, но забронировать не может | 8 с |
| E2E | после брони карточка хоста пропадает из каталога для остальных | — |

### Бронирование (§10)

| Уровень | Тест | Время |
|---|---|---|
| API | свободный слот — 201, статус `confirmed` | 54 мс |
| API | свой слот — 409 `cannot_book_own_slot` | 36 мс |
| API | слот в прошлом — 409 `slot_in_past` | 42 мс |
| API | нет такого слота — 404 | 41 мс |
| API | слот уже занят — 409 `slot_already_booked` | 88 мс |
| API | два одновременных запроса: подтверждена ровно одна бронь | 75 мс |
| E2E | свой слот по прямой ссылке забронировать нельзя, слот остаётся свободным | 9 с |
| E2E | слот, который уже начался, не бронируется | 1,8 мин |
| E2E | слот раньше чем через 25 минут после уже занятого не бронируется; ровно через 25 — бронируется | 10 с |
| E2E | основной путь: навык, слот, поиск, бронь, «Мои встречи» у обоих; второй гость тот же слот не забирает | — |

Гонка двух одновременных нажатий закрыта на API. В E2E второй гость бронирует следом, это занятый слот, а не параллельный запрос.

### Отмена (§11)

| Уровень | Тест | Время |
|---|---|---|
| E2E | отмену видят и хост, и гость | — |
| E2E | меньше чем за 2 часа отмена запрещена, слот остаётся забронированным | 13 с |
| E2E | ровно за 2 часа отмена проходит, слот снова свободен | 10 с |
| E2E | на минуту позже границы отмена проходит, и слот бронирует другой гость | 15 с |

Первый тест про то, что отмену видят обе стороны. Три следующих — про дедлайн в 2 часа и повторную бронь. Это разные вопросы.

### Мои встречи (§12)

| Уровень | Тест | Время |
|---|---|---|
| E2E | после брони встреча есть у обоих в «Ближайших» | внутри основного пути |
| E2E | когда встреча началась, она уходит из «Ближайших» в «Прошедшие и отменённые» у гостя и у хоста | 2,5 мин |

2,5 минуты — это ожидание реального старта слота, не простой браузера.

### Критерии приёмки (§13)

Сквозной путь из шести шагов собирает E2E «основной путь». Негативные пункты приёмки закрыты так:

| Критерий | Где |
|---|---|
| нельзя забронировать свой слот | API и E2E |
| нельзя забронировать уже занятый слот | API и второй гость в основном пути |
| нельзя создать слот в прошлом | E2E |
| нельзя отменить за час до звонка | E2E «меньше чем за 2 часа» — час попадает внутрь этого запрета |
| гонка не даёт две подтверждённые брони | API |

Вне MVP и без тестов: ссылка на созвон, уведомления, рейтинги, модерация, оплата.

## Что не является дублем

- Свой слот, слот в прошлом и занятый слот есть и в API, и в E2E. Мок отвечает за код ошибки, браузер — за текст и состояние экрана.
- Unit пересечения слотов не повторяет E2E про 25 минут: там разные объекты.
- Две ошибки входа (чужой email и чужой пароль) нужны вместе: сообщение не должно выдавать, какое поле неверно.
- Два типа навыка в запрете дубля — одно правило на `can_help` и на `want_to_learn`.

## Структура

```
src/pyramid/        чистые функции и локальный мок API
tests/unit/         пересечение слотов, формат времени, длина пароля
tests/api/          регистрация и бронирование по HTTP
tests/e2e/          сценарии в браузере
tests/Pages/        экраны: профиль, слоты, каталог, брони
tests/helpers/      пользователь, регистрация, часы, cleanup
requirements.md     спецификация, на неё ссылается матрица
```
